# User experience and screen inventory

Status: proposed journeys; no domain screens built or visual design approved.

## Navigation principles

Show active school/organizational context and responsibility clearly. Members should not see administrator-oriented navigation. Present only authorized context choices. Use plain Amharic/English labels, readable Ethiopic fonts, accessible errors, mobile-friendly controls and clear save states.

## Journeys and screens

| Journey | Proposed screens | Result |
|---|---|---|
| Member onboarding | Sign in/register or invite, choose/request association, pending status | Lead approves correct membership/account link |
| Member self-service | My profile, assigned forms, my submissions, notices/resources | Member maintains permitted data and finds information |
| Lead administration | School overview, membership requests, members, departments, appointments | Lead controls own school |
| Department coordination | Department overview, members, activities, participation, report drafts | Coordinator prepares local work and submissions |
| Local report release | Review queue, report detail, correction reason, approve/release | Approved version reaches designated upper office |
| Upper-office oversight | Branch overview, reporting completeness, released reports, review history | Officer reviews permitted scope and requests corrections |
| Union governance | Authorized overview, division scope, board resources | Distinct union responsibilities have distinct views |
| Sharing | Audience-filtered feed/library, item submission, publication review | Approved information exchanged across schools |

## State handling

Pending member access must explain who reviews it. Distinguish form draft, submitted and returned responses where applicable. Reports show draft, local review, returned, approved/released and higher review states without suggesting an unapproved draft is already delivered. Preserve user input across ordinary validation failures. Explain unsaved/network failure states without promising offline availability.

## Prototype and approval

Before substantial UI implementation, prepare a small screen/flow review for member profile, local lead overview, department report and upper completeness dashboard. Use fictional data. Existing foundation components are reusable primitives, not approved product designs. Record layout choices when reviewed; avoid implementing every screen in this inventory at once.
